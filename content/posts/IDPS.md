# 1. IDS란?

- **IDS, Intrusion Detection System**은 침입 탐지 시스템이다.
- 네트워크 트래픽, 시스템 로그, 파일 변경, 비정상 행위 등을 분석해 공격으로 의심되는 이벤트를 탐지하고 관리자에게 알림을 보낸다.
- 네트워크 트래픽의 복사본을 받아 분석
- 즉, 실제 트래픽 흐름 중간에 직접 끼어들기보다는, 스위치의 미러링 포트나 TAP 장비를 통해 트래픽을 관찰

```
사용자 → 방화벽 → 웹 서버
              ↓
          트래픽 복사본
              ↓
             IDS
              ↓
          탐지 / 로그 / 경고
```

- IDS는 공격을 탐지할 수 있지만, 기본적으로 직접 차단하지는 않는다. 그래서 IDS는 **보안 관제, 로그 분석, 침해사고 대응, 위협 헌팅**에 적합

| 탐지 대상 | 예시 |
| --- | --- |
| 네트워크 스캔 | Nmap 포트 스캔 |
| 웹 공격 | SQL Injection, XSS 패턴 |
| 악성코드 통신 | C2 서버 접속 |
| 비정상 패킷 | malformed packet |
| 내부 이상 행위 | 평소보다 많은 외부 전송 |

# 2. IPS란?

- **IPS, Intrusion Prevention System**은 침입 방지 시스템
- IDS처럼 공격을 탐지할 뿐만 아니라, 악성 트래픽으로 판단되면 **실시간으로 차단**
- 네트워크 경로 중간에 inline 방식으로 배

```
사용자 → 방화벽 → IPS → 웹 서버
```

| 대응 방식 | 설명 |
| --- | --- |
| 패킷 드롭 | 악성으로 판단된 패킷 폐기 |
| 세션 리셋 | 공격 세션 강제 종료 |
| IP 차단 | 공격 출발지 차단 |
| 룰 기반 차단 | 특정 공격 패턴 탐지 시 차단 |
| 방화벽 연동 | 탐지 결과를 방화벽 정책에 반영 |

# 3. IDS, IPS 차이

| 구분 | IDS | IPS |
| --- | --- | --- |
| 전체 이름 | Intrusion Detection System | Intrusion Prevention System |
| 핵심 목적 | 침입 탐지 | 침입 탐지 + 차단 |
| 배치 방식 | Out-of-band | Inline |
| 트래픽 처리 | 복사본 분석 | 실제 트래픽 검사 |
| 대응 방식 | 로그, 경고, 알림 | 패킷 차단, 세션 종료, IP 차단 |
| 장점 | 서비스 영향이 적고 분석에 유리 | 공격을 실시간으로 차단 가능 |
| 단점 | 직접 차단 불가 | 오탐 시 정상 서비스 차단 가능 |

# 4. IDS/IPS의 내부 동작 흐름

```bash
트래픽 또는 로그 수집
     ↓
전처리 및 정규화
     ↓
세션/프로토콜 분석
     ↓
탐지 엔진에서 룰 또는 모델 비교
     ↓
이벤트 생성
     ↓
경고 또는 차단
     ↓
로그 저장 및 SIEM 연동
```

## 4.1 트래픽 또는 로그 수집

- 분석할 데이터를 수집
- 수집 대상
    
    
    | 대상 | 예시 |
    | --- | --- |
    | 네트워크 패킷 | TCP, UDP, ICMP, HTTP, DNS |
    | 시스템 로그 | 로그인 로그, 인증 실패 로그 |
    | 애플리케이션 로그 | 웹 서버 로그, DB 접근 로그 |
    | 파일 변경 정보 | 중요 파일 수정, 삭제 |
    | 프로세스 행위 | 비정상 프로세스 실행 |
- **네트워크 기반 IDS** : 주로 스위치 미러링 포트, TAP 장비, 네트워크 센서에서 트래픽을 수집
- **호스트 기반 IDS** : 서버 내부에 설치되어 로그, 파일 무결성, 프로세스 행위 등을 감시

## 4.2 전처리 및 정규화

- 공격자는 같은 요청도 다양한 형태로 변형 할 수 있음
- ex) URL 인코딩, 대소문자 변경, 경로 변형, 패킷 분할 같은 방식으로 트래픽이 다르게 보일 수 있음
    
    ```bash
    %2e%2e%2f  →  ../
    /admin/../login  →  /login
    ```
    
- 공격자가 표현 방식을 바꾸더라도 IDS/IPS가 실제 의미를 해석 함
- IDS/IPS는 이를 분석하기 전에 가능한 한 동일한 의미의 요청을 같은 형태로 정규화

## 4.3 세션 및 프로토콜 분석

- IDS/IPS는 단일 패킷만 보는 것이 아니라, 여러 패킷을 하나의 흐름으로 재조립해 분석
- ex) TCP 통신은 여러 패킷으로 나뉘어 전달된다. IDS/IPS는 이를 다시 하나의 세션으로 이해해야 함

```bash
Packet 1: GET /lo
Packet 2: gin?id=
Packet 3: 1 HTTP/1.1

재조립 후:
GET /login?id=1 HTTP/1.1
```

- 또한 HTTP, DNS, TLS, SMB, FTP 같은 프로토콜 구조를 해석해 이상 여부를 판단

## 4.4 탐지 엔진

- 전처리와 세션 분석이 끝나면 탐지 엔진이 동작
- 시그니처 기반, 이상 행위 기반 탐지 등 기준을 이용

# 5. IDS/IPS의 탐지 방식

## 5.1 시그니처 기반 탐지

- 이미 알려진 공격 패턴을 룰로 만들어두고, 현재 트래픽이 해당 패턴과 일치하는지 확인하는 방식
- ex)
    
    ```bash
    ' OR '1'='1
    UNION SELECT
    <script>
    ../../etc/passwd
    ```
    

| 장점 | 알려진 공격에 대해 탐지 정확도가 높다 |
| --- | --- |
| 단점  | 로운 공격이나 변형된 공격에는 약할 수 있다 |

## 5.2 이상 행위 기반 탐지

- 정상적인 행위 기준선을 만들고, 그 기준에서 벗어난 행위를 공격 가능성으로 판단하는 방식

| 정상  | 이상 행위 |
| --- | --- |
| 로그인 요청 1분당 10회 | 로그인 요청 1분당 3,000회 |
| DB 서버는 외부 통신 거의 없음 | DB 서버가 외부 IP로 대량 통신 |
| 일반 사용자는 관리자 페이지 접근 안 함 | 일반 사용자 IP에서 `/admin` 반복 접근 |

| 장점 | 알려지지 않은 공격도 탐지할 가능성이 있다 |
| --- | --- |
| 단점  | 정상적인 급증 트래픽도 공격으로 오인 |

## 5.3 상태 기반 프로토콜 분석

- 프로토콜이 정상적으로 동작하는 순서와 구조를 기준으로 이상 여부를 판단하는 방식
- ex) TCP, HTTP 정상 요청 응답 구조를 알고 있다가, 비정상적인 흐름이 발생하면 탐지
    
    ```bash
    정상 HTTP 요청:
    GET /index.html HTTP/1.1
    Host: [example.com](http://example.com/)
    
    비정상 요청:
    HTTP 구조에 맞지 않는 헤더
    비정상적으로 긴 필드
    잘못된 프로토콜 순서
    허용되지 않는 명령 사용
    ```
    

| 장점 | 높은 탐지 정확도, 프로토콜 오용 차단 |
| --- | --- |
| 단점  | 높은 리소스 소모, 성능 저하(Latency) |

# 6. IDS/IPS의 유형

| 유형 | 설명 | 예시 |
| --- | --- | --- |
| NIDS | 네트워크 트래픽을 분석하는 IDS | 스위치 미러링 트래픽 분석 |
| NIPS | 네트워크 중간에서 트래픽을 차단하는 IPS | 방화벽 뒤 inline IPS |
| HIDS | 호스트 내부 로그, 파일, 프로세스 감시 | 서버 로그 분석, 파일 변조 탐지 |
| HIPS | 호스트 내부에서 악성 행위 차단 | 악성 프로세스 실행 차단 |
| WIDS/WIPS | 무선 네트워크 침입 탐지/차단 | Rogue AP 탐지 |
| NBA/NBAD | 네트워크 행위 기반 이상 탐지 | 비정상 대용량 전송 탐지 |

## 6.1 NIDS / NIPS

- NIDS, Network-based IDS
    - 네트워크 구간의 트래픽을 분석
- NIPS, Network-based IPS
    - 네트워크 중간에서 트래픽을 분석하고 차단

```bash
NIDS:
스위치 미러링 → 트래픽 복사본 분석 → 경고

NIPS:
사용자 → NIPS → 서버
        악성 트래픽 차단
```

- 배치 위치

```bash
인터넷 경계 구간
DMZ 구간
웹 서버 앞단
내부망 중요 구간
데이터센터 구간
```

| 탐지 대상 | 예시 |
| --- | --- |
| 포트 스캔 | 다수 포트 접근 시도 |
| 웹 공격 | SQL Injection, XSS 시도 |
| 악성코드 통신 | C2 서버 접속 |
| 비정상 DNS | DGA 도메인 요청 |
| 취약점 공격 | 특정 CVE 익스플로잇 패턴 |
| DoS/DDoS | 비정상 대량 요청 |

## 6.2 HIDS / HIPS

- **HIDS,** Host-based IDS
    - 서버나 PC 내부에 설치되어 시스템 행위를 감시
    - 암호화된 트래픽 이후의 실제 서버 내부 행위를 볼 수 있음
- **HIPS,** Host-based IPS
    - 호스트 내부에서 악성 행위를 탐지하고 차단
- 네트워크 패킷보다 **호스트 내부 정보**를 더 잘 볼 수 있음

| 감시 대상 | 예시 |
| --- | --- |
| 파일 무결성 | `/etc/passwd`, 웹 소스코드 변경 |
| 로그인 로그 | SSH 로그인 실패 |
| 프로세스 | 비정상 프로세스 실행 |
| 레지스트리 | Windows 자동 실행 등록 |
| 권한 상승 | 관리자 권한 획득 시도 |
| 시스템 호출 | 비정상 syscall 패턴 |

## 6.3 WIDS / WIPS

- 무선 네트워크 환경을 감시하거나 차단하는 시스템

| 탐지 대상 | 설명 |
| --- | --- |
| Rogue AP | 승인되지 않은 무선 AP |
| Evil Twin | 정상 AP처럼 위장한 가짜 AP |
| 비인가 단말 | 허가되지 않은 무선 접속 |
| 무선 DoS | 무선 인증 해제 공격 등 |
| 취약 암호화 | 취약한 무선 보안 설정 |

## 6.4 NBA / NBAD

- NBA, Network Behavior Analysis
- 네트워크 행위를 분석하는 방식
- 단순한 패킷 시그니처보다 네트워크 흐름의 이상 패턴을 관찰
- 침해 탐지, 계정 탈취, 내부 이동 탐지에 유용

```bash
ex)
특정 내부 PC가 갑자기 여러 서버로 접속
내부 DB 서버가 외부로 대량 데이터 전송
평소 접속하지 않던 국가 IP와 통신
DNS 요청이 비정상적으로 증가
내부망에서 lateral movement 의심 행위 발생
```

# 7. IDS/IPS 운영에서 중요한 점

## 7.1 룰 튜닝

- IDS/IPS는 룰을 기반으로 동작하는 경우가 많음
- 특정 패킷에 대해  동작할지 결정
    
    ```bash
    어떤 트래픽을 볼 것인가?
    어떤 문자열이나 패턴을 찾을 것인가?
    어떤 조건에서 경고할 것인가?
    탐지되면 어떤 메시지를 출력할 것인가?
    심각도는 어느 정도인가?
    ```
    
- ex)
    
    ```bash
    alert tcp any any -> any 80 (
        msg:"Suspicious HTTP test pattern";
        content:"test-pattern";
        sid:1000001;
        rev:1;
    )
    ```
    

| 항목 | 의미 |
| --- | --- |
| alert | 탐지 시 경고 발생 |
| tcp | TCP 트래픽 대상 |
| any any | 출발지 IP와 포트 |
| any 80 | 목적지 IP와 80번 포트 |
| msg | 경고 메시지 |
| content | 탐지할 문자열 |
| sid | 룰 고유 ID |
| rev | 룰 버전 |
- 모든 룰을 켜면 오탐 증가, 로그 폭증, 중요 이벤트 누락, 선능 저하와 같은 문제가 발생함
- **운영 환경에 맞게 룰을 조정해야 함**
    
    
    | 튜닝 대상 | 설명 |
    | --- | --- |
    | 불필요한 룰 비활성화 | 사용하지 않는 서비스 관련 룰 제거 |
    | 중요 자산 우선 적용 | DB, 웹 서버, AD 서버 중심 탐지 |
    | 임계값 조정 | 반복 요청 기준 조정 |
    | 화이트리스트 관리 | 정상 관리 서버 제외 |
    | 차단 룰 신중 적용 | 오탐 가능성이 낮은 룰부터 차단 |

## 7.2 오탐과 미탐 관리

| 개념 | 설명 |
| --- | --- |
| 오탐 | 정상 행위를 공격으로 탐지 |
| 미탐 | 공격 행위를 탐지하지 못함 |
- IPS에서는 오탐 : 정상 요청을 차단하면 서비스 장애로 이어질 수 있음
- 미탐이 많으면 실제 공격을 놓침
- 좋은 운영은 오탐과 미탐 사이의 균형을 잡는 것

## 7.3 로그 분석과 SIEM 연동

- 탐지 결과는 단독으로 보기보다 SIEM과 연동해 분석하는 것이 효과적
- **SIEM,** **Security Information and Event Management**
    - 여러 보안 장비와 서버에서 발생하는 로그를 중앙에서 수집하고, 상관분석하여 침해 사고 가능성을 탐지하는 보안 관제 시스템
    - 여러 탐지 결과와 시스템 로그를 연결해 전체 공격 흐름을 파악하는 역할

```bash
IDS/IPS 로그 , 방화벽 로그 , WAF 로그
서버 로그 , EDR 로그 , 인증 로그
        ↓
       SIEM
        ↓
상관분석 / 경보 / 사고 대응
```

## 8. 최종 요약

- IDS/IPS의 핵심은 **장비 설치**가 아니라 **운영**
- 룰을 최신 상태로 유지하고, 환경에 맞게 조정하며, 탐지 로그를 SIEM이나 관제 시스템과 연동해 실제 사고 대응으로 이어지게 해야 한다.
- IDS/IPS는 단독으로 완벽한 방어를 제공하는 기술이 아닌, 방화벽, WAF, EDR, SIEM과 함께 다층 방어 체계를 구성할 때 효과가 가장 커진다
