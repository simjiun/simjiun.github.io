# Coinbase 고객 데이터 유출 사고 분석: 내부자 접근 권한 관리 실패 사례

![image.png](/images/coinbase.png)

# 사건 개요

- 2025년 5월, 미국 암호화폐 거래소 **Coinbase**에서 고객 데이터 유출 사고가 발생했다.
- 이 사고는 **고객지원 업무를 담당하던 해외 지원 인력을 금전적으로 포섭해 고객 정보를 빼낸 내부자 기반 보안 사고**에 가깝다.
- Coinbase는 2025년 5월 15일 공식 블로그를 통해, 공격자들이 해외 고객지원 담당자 일부를 금전적으로 포섭했고, 이들이 고객지원 시스템에서 접근 가능한 고객 정보를 복사했다고 밝혔다. 공격자의 목적은 해당 정보를 이용해 Coinbase를 사칭하고, 고객에게 사회공학 공격을 수행하는 것이었다.
- 이후 공격자는 Coinbase에 **2,000만 달러**를 요구했지만, Coinbase는 이를 지불하지 않았다. 대신 범인 검거에 도움이 되는 정보를 제공하는 사람에게 2,000만 달러의 보상금을 지급하겠다고 발표했다

# 근본 원인 분석

## 1. 내부자 포섭

- 이번 사고의 가장 직접적인 원인은 **내부자 포섭**이다.
- Coinbase는 공격자들이 해외 고객지원 담당자 일부에게 금전적 보상을 제안했고, 이들이 고객지원 도구에서 데이터를 복사했다고 설명했다.

## 2. 고객지원 시스템 접근 권한 관리 문제

- 고객지원 담당자는 업무 특성상 고객 정보를 확인해야 한다.
- 하지만 이번 사고에서는 고객지원 담당자가 접근할 수 있던 정보가 공격자에게 넘어갔다.
- SEC 공시에서도 공격자는 미국 외부의 지원 역할을 수행하던 계약자 또는 직원에게 돈을 지급했고, 이들이 업무상 접근 가능한 내부 시스템에서 정보를 수집한 것으로 보인다고 설명한다.
- 문제는 고객지원 인력이 정보를 볼 수 있었다는 사실 자체보다, **민감한 정보를 조회하거나 복사하는 행위가 충분히 제한·감시되지 않았다는 점**이다.

## 3. 내부자 이상 행위 탐지 후 대응의 한계

- Coinbase는 이전 몇 달 동안 업무상 필요 없이 데이터에 접근한 사례를 보안 모니터링으로 탐지했고, 관련 인력을 해고했다고 밝혔다.
- 하지만 이후 공격자의 금전 요구 이메일을 받은 뒤, 이전의 부적절한 접근 사례들이 하나의 공격 캠페인에 속한다고 판단했다.

```
이상 접근 탐지
   ↓
관련 인력 해고
   ↓
하지만 전체 공격 캠페인으로 연결해 파악하는 데는 시간 소요
   ↓
공격자는 이미 일부 고객 정보를 확보
```

- 즉, 탐지 자체는 이루어졌지만, 여러 건의 이상 접근을 하나의 조직적 공격으로 빠르게 연결하고 확산을 차단하는 데는 한계가 있었다고 볼 수 있다.

## 4. 외주 고객지원 운영의 보안 리스크

- 보안뉴스 보도에 따르면 공격자들은 Coinbase 시스템 접근 권한을 얻기 위해 인도 고객지원 외주 기업 TaskUs 직원들을 뇌물로 매수한 것으로 드러났다.
- 외주 고객지원 운영은 비용과 효율성 측면에서 장점이 있지만, 민감한 금융 정보를 다루는 서비스에서는 보안 리스크가 커질 수 있다.

```
고객지원 업무 외주화
   ↓
외부 인력이 고객 정보 접근
   ↓
접근 권한 관리와 물리적 통제가 약하면 정보 복사 가능
   ↓
내부자 포섭 시 데이터 유출로 이어짐
```

- 특히 암호화폐 거래소처럼 고객 자산과 신원정보를 함께 다루는 서비스는 외주 인력에게도 내부 직원과 동일하거나 더 강한 보안 통제를 적용해야 한다.

## 보완이 미흡했던 부분

## 1. 고객지원 담당자의 데이터 접근 범위가 넓었음

- 고객지원 업무에는 고객 정보 접근이 필요하다. 하지만 모든 상담원이 모든 민감 정보에 접근할 필요는 없다.
- 업무 유형에 따라 접근 권한을 더 세분화했어야 한다.

```
단순 문의 처리 → 기본 계정 정보만 접근
본인 인증 문제 → 제한된 KYC 정보 접근
고위험 계정 조치 → 별도 승인 후 민감 정보 접근
대량 조회 → 자동 차단 또는 관리자 승인 필요
```

## 2. 이상 접근 탐지 후 전체 공격 캠페인 파악이 늦었음

Coinbase는 업무상 필요 없는 데이터 접근을 이전에 탐지했지만, 이후 공격자의 금전 요구를 받은 뒤 해당 접근들이 하나의 공격 캠페인에 속한다고 판단했다.

이는 단일 이상 행위 탐지는 가능했지만, 여러 계정에서 발생하는 이상 접근을 연결해 큰 공격 흐름으로 분석하는 체계가 더 강화될 필요가 있었다는 점을 보여준다.

## 3. 외주 인력에 대한 관리적·물리적 통제가 부족했음

보안뉴스 보도 기준으로는 TaskUs 직원 2명이 연루되었고, 이후 해당 부서 인원 226명이 해고되었다.

이 내용은 외주 인력에게 민감 정보 접근 권한을 부여할 때 단순 계정 권한 관리만으로는 부족하다는 점을 보여준다.

필요한 통제는 다음과 같다.

```
- 개인 휴대폰 사용 제한
- 화면 촬영 방지
- 대량 조회 탐지
- 민감 정보 접근 시 사유 기록
- 외주업체 보안 감사
- 고위험 업무 분리
```

# 재발 방지 대책

## 1. 최소 권한 원칙 적용

- 고객지원 담당자는 업무에 필요한 정보만 볼 수 있어야 한다.

## 2. 내부자 위협 탐지 강화

- 내부자가 고객 정보를 비정상적으로 조회하는 행동을 빠르게 탐지해야 한다.
- 이런 행위가 발생하면 단순 경고에 그치지 않고, 계정 일시 정지, 관리자 검토, 접근 범위 분석까지 이어져야 한다

## 3. 외주 인력 보안 통제 강화

- 외주 고객지원 인력도 내부 직원과 동일한 수준의 보안 통제를 받아야 한다.
- 특히 금융, 암호화폐, 의료, 교육처럼 민감한 개인정보를 다루는 조직은 외주업체의 보안 수준까지 직접 점검해야 한다.

# 기술적 대응 방법

### 1. 역할 기반 접근 제어, RBAC 강화

- 고객지원 담당자가 모든 고객 정보를 볼 수 있으면 내부자 사고가 발생했을 때 피해 범위가 커진다. 따라서 상담원 역할별로 접근 가능한 정보를 세분화

### 2. 민감 정보 마스킹

- 고객지원 화면에서 민감 정보를 그대로 보여주지 말고 기본적으로 마스킹

### 3. Just-in-Time 접근 권한

- 상담원이 민감 정보를 항상 볼 수 있게 하면 위험하다. 대신 필요한 순간에만 임시 권한을 부여하는 방식 사용
